# apps/web (landing page + install script) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new `@rsynx/web` workspace app that serves the `rsynx.ir` landing page at `/` and a POSIX install script at `/i`, both as static files behind a bare `Bun.serve()` — no framework, no build step.

**Architecture:** Mirrors `apps/relay`'s shape exactly: a `createServer(port)` function in `src/server.ts` that returns `Bun.serve({...})`, and a thin `src/index.ts` entrypoint that calls it and logs a JSON line. The fetch handler maps three routes (`/`, `/i`, everything else → 404) to two static files under `public/`, read via `Bun.file()` with paths resolved off `import.meta.dir` (so it works regardless of the process's cwd).

**Tech Stack:** Bun only (`Bun.serve`, `Bun.file`, `bun:test`) — no HTTP framework, no bundler, no client-side JS.

**Spec:** `docs/superpowers/specs/2026-09-06-apps-web-design.md`

## Global Constraints

- Bun only — no npm/yarn/pnpm, no Node.js runtime, anywhere in this app.
- `strict: true` TypeScript (inherited automatically via `tsconfig.json`'s `extends: "../../tsconfig.json"`).
- File names: kebab-case.
- Commit messages: Conventional Commits, one per logical step.
- GitHub repo is `arazshah/rsynx` — the install script and landing page both hardcode this.
- The install script never uses `sudo` and never writes outside `$HOME` unless the user sets `RSYNX_INSTALL_DIR` explicitly.
- No build step, no frontend framework, no separate CSS/JS files — the landing page is one static HTML file with inline `<style>` and no `<script>`.

- [ ] **Step 4: Write the install script**

Create `apps/web/public/install.sh`:

```sh
#!/bin/sh
set -e

REPO="arazshah/rsynx"
INSTALL_DIR="${RSYNX_INSTALL_DIR:-$HOME/.local/bin}"

os=$(uname -s)
case "$os" in
  Linux) os="linux" ;;
  Darwin) os="darwin" ;;
  *)
    echo "rsynx: unsupported OS: $os" >&2
    echo "Download a binary manually: https://github.com/$REPO/releases" >&2
    exit 1
    ;;
esac

arch=$(uname -m)
case "$arch" in
  x86_64|amd64) arch="x64" ;;
  arm64|aarch64) arch="arm64" ;;
  *)
    echo "rsynx: unsupported architecture: $arch" >&2
    echo "Download a binary manually: https://github.com/$REPO/releases" >&2
    exit 1
    ;;
esac

asset="rsynx-${os}-${arch}"
url="https://github.com/$REPO/releases/latest/download/$asset"

mkdir -p "$INSTALL_DIR"
tmp=$(mktemp)
echo "Downloading $asset..."
curl -fsSL "$url" -o "$tmp"
chmod +x "$tmp"
mv "$tmp" "$INSTALL_DIR/rsynx"

echo "rsynx installed to $INSTALL_DIR/rsynx"

case ":$PATH:" in
  *":$INSTALL_DIR:"*) ;;
  *)
    echo ""
    echo "Add it to your PATH:"
    echo "  export PATH=\"$INSTALL_DIR:\$PATH\""
    ;;
esac
```

Run: `chmod +x apps/web/public/install.sh`

- [ ] **Step 7: Implement the server**

Create `apps/web/src/server.ts`:

```ts
const PUBLIC_DIR = `${import.meta.dir}/../public`;

/**
 * Serves the static landing page and install script. No framework, no
 * build step — apps/relay's Bun.serve()-only pattern, extended to files.
 */
export function createServer(port: number) {
  return Bun.serve({
    port,
    fetch(req) {
      const { pathname } = new URL(req.url);

      if (pathname === "/") {
        return new Response(Bun.file(`${PUBLIC_DIR}/index.html`), {
          headers: { "content-type": "text/html; charset=utf-8" },
        });
      }

      if (pathname === "/i") {
        return new Response(Bun.file(`${PUBLIC_DIR}/install.sh`), {
          headers: { "content-type": "text/x-shellscript; charset=utf-8" },
        });
      }

      return new Response("Not Found", { status: 404 });
    },
  });
}
```
